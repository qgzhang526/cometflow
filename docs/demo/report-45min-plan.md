## 3. 原理部分怎么讲（第 7–15 页）

每段结构固定：**一句话结论 → 机器怎么保证 → 现场在哪一页能看到**。

| 段 | 一句话结论 | 支撑机制 | 现场对应 |
|---|---|---|---|
| ① 单一事实源 | 人类只写两个地方 | 其余全是机器投影；同一事实只有一个 owner | 第 18 页改错错误码 |
| ② 契约可派生 | 一个接口一个锚点 | 引用是结构化的，不是说明文字 | 第 18 页校验 |
| ③ 验收可执行 | 每条验收挂着一条命令 | 写不出 check 会被单独标出来 | 第 19 页验收覆盖 |
| ④ 拆解不靠模型 | 任务由锚点派生 | 评审与批准留给人 | 第 19 页计划面板 |
| ⑤ 冻结即契约 | acceptance 与 spec_hash 锁死 | 执行阶段不再重新解释规格 | 第 20 页变更详情 |
| ⑥ 生成与评价分离 | 实现者不能宣布完成 | 判定来源标在方括号里；有界修复 | 第 20 页验收 |
| ⑦ 边界与托管 | 越界拒绝；判不了卷就停机 | 模块归属、准入检查、预算与租约 | 第 21 页调度 |

## 6. 风险与预案

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 真 Agent 变慢或写不完 | 超过 5 分钟没结束 | 说「这正是不可自证完成」，点验收展示判 fail 退回构建，然后切录屏 |
| 调度面板出现重复行 | 队列里同一条任务出现两次 | 这个缺陷已经修了（见第 9 节第 1 条）。万一还看到，`preflight.ps1` 会先报出来 |
| `serve` 找不到前端产物 | 启动时提示 `web 下没有 index.html` | 在 cometflow 仓库目录里启动，或加 `--web-dir <repo>\web\dist` |
| 端口冲突 | 启动报 EADDRINUSE | 换 `--port 4400` |
| 浏览器没带 token | 页面空白或 401 | 用启动时打印的完整地址重新打开 |
| 时间超了 | 到 39 分钟还没进桥段四 | 桥段四只放兜底项目的队列，桥段五只放总览 |

## 7. Q&A 备答

| 提问 | 备答要点 |
|---|---|
| 这不就是 Cursor / Claude Code 吗？ | 那些是帮你写；这套东西管的是写完之后怎么判定、怎么留痕、怎么托管。判定权不在实现者手里 |
| 为什么非得写 spec？ | 没有 spec 就没有可判定的验收。18 条 check 就是这个成本的去向 |
| 判据谁写？成本更高吗？ | 人写或 Agent 起草、人定稿。判据前置一次，之后每次执行都复用 |
| 无人值守跑错了怎么办？ | 预算上限、有界修复循环、门禁、git 漂移阻断；验收不可判定时直接停机 |
| 和现有 CI 什么关系？ | 门禁与 CI 是同一份实现，本地和流水线判定一致 |
| 换模型 / 换 Agent 要改多少？ | AgentRunner 只有四个方法，本机 opencode 与 claude-code 都可用，mock 用于离线兜底 |
| 演示环境是特制的吗？ | 两个仓库都由 `prepare-demo.ps1` 从种子生成，脚本在仓库里，可以自己跑 |

## 9. 已知瑕疵（如实说，不藏）

| # | 现象 | 性质 | 影响与处理 |
|---|---|---|---|
| 1 | ~~调度队列出现重复行~~ | **已修复** | 根因是 `domains/scheduler/daemon-todo.ts` 的 `mergeTodoView` 在「运行时记录不是 queued」分支里漏了 `overlayById.delete(key)`，末尾的孤儿合并把同一条再追加一次。已补上该行，并在 `test/domains/daemon-todo.test.ts` 加了「同一条任务只出现一次、且连续 rebuild 稳定」的回归用例；全量 598 个测试通过，`preflight.ps1` 也加了幂等断言 |
| 2 | CBB 种子跑 `spec validate` 会带 6 条 warning（1 个未引用模型 + 5 条未引用规则） | 种子内容问题，不是平台缺陷 | 可以补引用清零，也可以当成「问题清单」的演示素材 |
| 3 | `plan_review: high-risk` 的高风险识别规则未实现 | 已知未实现的功能，有兜底 | 演示仓库显式写成 `human`，提示语干净且语义一致 |

| 5 | `node tests/acceptance.mjs` 在 Node 24 打印 SQLite 实验性告警 | 运行环境噪声 | 无害，一句带过 |
| 6 | `change verify` 先打印一行 Agent 版本号 | 输出噪声（很小） | 无害 |
| 7 | `change run` 期间 Agent 偶尔打印 `The user rejected permission to use this specific tool call` | Agent 侧行为 | Agent 想写临时文件自测时被自己的权限策略挡了一下，实测不影响交付 |

## 10. 复现这套环境

