# 项目使命

用 CometFlow 自身（spec 驱动 + 自动拆解 + 真实 Agent + eval 门禁 + evolve 进化）开发一款可玩、可测、可自动评估的终端 2048 游戏，并产出平台首个「自举验证报告」。

## 任务目标

### G1：2048 核心引擎
- 目标：以纯 TypeScript 实现 4×4 棋盘、移动合并、计分与胜负判定
- 范围：core
- 成功标准：
  - 棋盘移动合并与计分全部通过确定性单测
  - 随机源可注入，支持固定种子复现
  - 核心逻辑不依赖任何渲染或输入库
- 非目标：
  - 不做任何图形界面
  - 不做 AI 决策

### G2：终端玩法闭环
- 目标：提供终端交互玩法，WASD/方向键操控、渲染、退出与重开
- 范围：cli
- 成功标准：
  - 玩家可完成一局完整对局（启动→移动→结束）
  - 支持非 TTY 快照输出，便于自动化验收
  - 非法输入不崩溃
- 非目标：
  - 不做图形/网页界面
  - 不做高分持久化（见 G4）

### G3：AI 玩家与 benchmark
- 目标：实现可配置深度的 AI 玩家与 benchmark 自动评估
- 范围：ai
- 成功标准：
  - benchmark 以固定种子运行 100 局并输出 JSON 指标
  - 指标包含 max tile、总分、移动数、达到 2048 的胜率
  - 单局思考时间有界（可配置超时）
- 非目标：
  - 不做强化学习训练
  - 不做多人对战

### G4：高分持久化
- 目标：本地持久化最高分与统计
- 范围：persistence
- 成功标准：
  - 最高分在重开后仍可读取
  - 损坏文件可安全恢复（不崩溃）
  - 存储位置遵循跨平台约定
- 非目标：
  - 不做云端同步

### G5：自举验证报告
- 目标：汇总无人值守执行、eval 门禁、evolve 进化的全过程数据，形成平台验证报告
- 范围：report
- 成功标准：
  - 报告覆盖 H1~H4 四条假设，逐条给出数据与判定
  - 记录平台自身发现的缺陷或改进项
  - 报告落在 reports/ 目录且可被 spec trace 引用
- 非目标：
  - 不做平台代码改动（缺陷只记录，不修复）
