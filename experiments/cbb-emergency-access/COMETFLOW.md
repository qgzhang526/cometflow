# 项目使命

CBB-应急运维接入（Emergency Access）：为被防火墙策略封锁了 SSH 的生产服务器，提供一条**显式授权、强认证、有时限、全审计**的应急运维通道，作为可被多个运维平台复用的公共构建块（CBB）。

本仓库是**可被 Agent 重建的参考工程**：契约（本文 + `specs/`）与判据（`tests/acceptance.mjs`）先写，
实现（`src/`）在 CometFlow 的 change / daemon 通道里产出。判据在实现产出前会失败，这是设计意图。

## 模块归属

每个 capability 的实现限定在各自 `specs/<capability>/spec.md` front-matter 声明的 `module` 内。
以下路径跨 capability 共享，允许在任何任务的模块之外改动：

| 共享路径 | 说明 |
|----------|------|
| src/server.mjs | 服务入口：HTTP 路由、认证、响应包络（见 protocol.md「服务入口」） |
| src/store.mjs | 存储层：实体表与 append-only 审计（见 models.md） |
| tests | 判据执行器与夹具，不属于任何 capability 模块 |
| package.json | 依赖清单与脚本；本项目零外部依赖，只允许用 Node 内置模块 |

## 任务目标

### G1：应急接入的申请、审批与吊销
- 目标：提供显式的接入申请、审批与吊销能力，并发放一次性令牌
- 范围：access
- 成功标准：
  - 每次接入都必须有申请单、审批记录与一次性令牌，三者可互相追溯
  - 未审批的申请无法获得任何通道
  - 申请人不能审批自己的申请
- 非目标：
  - 不做账号体系与登录（复用现有管理平台的账号与 MFA）
  - 不做隐藏入口，也不做任何口令式触发

### G2：临时通道的建立、回收与会话守卫
- 目标：在授权有效期内建立到目标服务器 SSH 的临时通道，并在到期或空闲时强制回收；
  实际转发由「转发器适配器」执行（见 tunnel/spec.md），本 CBB 负责授权的判定与生命周期
- 范围：tunnel, guard
- 成功标准：
  - 通道只在授权有效期内存在，来源 IP 不在白名单时拒绝建立
  - 会话超过最长时长或空闲超时后，通道与临时账号被强制回收
  - 回收后转发规则恢复原状，不残留
- 非目标：
  - 不修改物理防火墙策略
  - 不把 SSH 暴露给白名单之外的来源
  - 不在本 CBB 内实现 SSH 协议（交给转发器适配器）

### G3：审计、告警与取证
- 目标：全链路留痕，关键动作实时通知安全团队，支持事后取证导出
- 范围：audit
- 成功标准：
  - 申请、审批、开启、回收均有审计事件，且写入为 append-only
  - 关键动作在 5 秒内推送到告警通道
  - 审计可按时间范围导出，导出行为本身也被记录
- 非目标：
  - 不做长期归档存储（转交 SIEM）
