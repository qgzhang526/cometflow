# 非功能约束

## 安全约束

- 所有接入必须经过现有管理平台的登录与 MFA，不引入独立的弱认证通道
- 禁止隐藏入口、密语式触发与共享口令
- 一次性令牌只在发放时返回一次，落库只存哈希
- 通道只对配置白名单内的来源开放，默认拒绝
- 不在服务端保存明文口令
- `auth.mode=header` 只允许在演练与验收环境使用；生产必须为 `platform`，否则任何人构造两个 HTTP 头即可冒充审批人

## 审计约束

- 所有状态变更写入 append-only 审计流，禁止原地修改
- 审计事件包含 actor 与来源地址，保留期不少于 audit.retention_days
- 导出行为本身也必须被记录

## 可判定性约束

- 每条验收都必须能用一条可执行命令判定：spec 里的 Acceptance 项带 `- check:`，
  实现产出前该命令失败、产出后通过，不依赖人的印象
- 一切外部依赖（SSH 转发、系统时钟、管理平台会话）必须做成可替换的适配器接缝，
  接缝名与默认值由 config.md 与各 capability spec 约定；验收用 tests/fixtures/ 下的替身
- 验收执行器只允许依赖 Node 内置模块，不允许依赖外部测试框架或网络

## 性能约束

| 指标 | 目标值 |
|------|--------|
| 审批通过到通道可用 | 小于 10 秒 |
| 超过时限后通道回收延迟 | 小于 30 秒 |
| 审计写入对主流程的影响 | 小于 50 毫秒 |

## 高可用约束

- 守卫进程重启后必须依据持久化状态完成回收，不允许出现孤儿通道
- 回收失败必须重试并告警，不允许静默失败

## 部署约束

- 与现有配置管理平台同机部署，不新增对外监听端口
- 不修改物理防火墙策略，访问控制变更走独立变更流程
- 默认转发器适配器（`src/tunnel/forwarder.mjs`）只维护规则表、不建立真实 SSH 连接，
  属于演练适配器，禁止用于生产；生产部署必须由 `tunnel.forwarder_module` 指定真实转发实现

## 离线依赖管理

- 只使用 Node 标准库：SQLite 走 Node 24 内置的 `node:sqlite`，不引入第三方驱动
- 不新增任何 npm 依赖；确有必要时，必须随包提供离线 tarball 与校验和
